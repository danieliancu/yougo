Raport YouGo - stadiu si directie

1. CE ESTE IMPLEMENTAT ACUM

Appointment Mode
- Mod functional de baza.
- Pentru businessuri unde clientii programeaza un serviciu la o data si ora.
- Exemple: salon, clinica, dentist, service auto, consultant, terapeut, cursuri.
- Colecteaza serviciu, locatie, staff, data, ora, nume si telefon.
- Creeaza programari in dashboard.

Website Chat
- Widgetul de website functioneaza.
- AI-ul poate ghida clientii si poate crea cereri de programare.
- Chatul de website are comportament de conversatie noua prin butonul +.

WhatsApp AI
- WhatsApp inbound/outbound functioneaza.
- Raspunsurile sunt procesate prin queue/job.
- Exista deduplicare.
- Statusurile de livrare si citire sunt urmarite.
- Exista onboarding pentru sender real.
- Exista context recent de programare, astfel incat AI-ul poate raspunde despre statusul unei programari anterioare chiar daca in dashboard conversatia este vizual noua.

Business Dashboard
- Businessul poate gestiona servicii, staff, locatii, programari, conversatii, setari AI, widget, WhatsApp, billing si setari.

Platform Admin
- Exista admin intern YouGo.
- Afiseaza businessuri, usage, onboarding WhatsApp si issues.
- Platform Admin este separat de dashboardul businessului.
- Campurile tehnice WhatsApp sunt tinute in afara dashboardului normal al businessului.

Usage / Limits
- Usage-ul este urmarit si vizibil.
- Sunt disponibile mesaje WhatsApp, programari, consum chat si limite de plan.

WhatsApp Onboarding Queue
- Businessurile pot cere activarea WhatsApp.
- Detaliile pentru setup call sunt salvate.
- Platform Admin afiseaza coada de activare si comanda de activare.

CRM Light
- Exista tabela de clienti.
- Programarile si conversatiile sunt legate de clienti.
- Businessul are /dashboard/customers si pagini de detaliu pentru clienti.
- Matchingul se face dupa telefon mai intai, apoi email, niciodata doar dupa nume.
- CRM-ul nu este conectat inca la prompturile AI.

2. CE MAI ESTE DE FACUT

Lead Mode
- Status: neimplementat ca flux real.
- Scop: pentru businessuri care nu au nevoie de programari exacte.
- AI-ul colecteaza o cerere/lead in loc sa creeze o programare.
- Exemple: avocati, contabili, imobiliare, agentii, constructii, vanzari auto, servicii profesionale.
- Flow:
  - Ce cauti?
  - Buget?
  - Locatie?
  - Urgenta?
  - Nume?
  - Telefon/email?
- Rezultat: leadul apare in dashboard pentru follow-up de catre business.
- De ce primul:
  - Este mai simplu decat Reservation Mode.
  - Nu necesita disponibilitate, sloturi, capacitate sau telefonie.

Reservation Mode
- Status: neimplementat ca flux real.
- Scop: pentru businessuri unde clientii rezerva o resursa sau un loc, nu o programare pentru un serviciu.
- Exemple: restaurante, hoteluri, inchirieri, inchirieri auto, inchirieri echipamente, spatii pentru evenimente, experiente.
- Flow:
  - Ce resursa/loc?
  - De cand?
  - Pana cand?
  - Cate persoane/articole?
  - Preferinte?
  - Date de contact?
- Rezultat: cererea de rezervare apare in dashboard.
- De ce al doilea:
  - Este mai complex decat Lead Mode.
  - Are nevoie de logica pentru disponibilitate, capacitate si resurse.

Phone AI
- Status: neimplementat.
- Scop: AI-ul preia sau asista apeluri telefonice.
- Clarificare importanta:
  - Phone AI este canal de comunicare, nu mod de business.
  - Trebuie sa foloseasca ulterior Appointment Mode, Lead Mode sau Reservation Mode.
- Necesita:
  - provider de telefonie
  - speech-to-text
  - text-to-speech
  - transcript apel
  - tracking de minute
  - control costuri
  - fallback/handoff
- De ce ultimul:
  - Are cea mai mare complexitate.
  - Trebuie construit dupa ce modurile de business sunt clare.

Concluzie

Baza YouGo este stabila: Appointment Mode, Website Chat, WhatsApp AI, Platform Admin, Usage, WhatsApp Onboarding si CRM Light exista deja ca MVP. De aici inainte, focusul trebuie restrans la trei extinderi esentiale: Lead Mode, Reservation Mode si Phone AI.

Ordinea de lucru recomandata: Lead Mode -> Reservation Mode -> Phone AI.
